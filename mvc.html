Modelo-Vista-Controlador (MVC)

El patrón de arquitectura de software que separa la lógica de negocio, la interfaz y la entrada del usuario

¿Qué es el patrón MVC?

MVC es un patrón de diseño de software que separa una aplicación en tres componentes interconectados: Modelo, Vista y Controlador. Esto permite una separación de preocupaciones, es decir, cada componente se encarga de un aspecto específico de la aplicación, facilitando el desarrollo, testing y mantenimiento.

Modelo

Gestiona los datos y la lógica de negocio. Es responsable de acceder a la base de datos, procesar información y aplicar reglas de negocio.

  • Gestión de datos
  • Lógica de negocio
  • Validación de datos
  • Acceso a base de datos

Vista

Presenta la información al usuario. Es la interfaz visual que muestra datos y recibe interacciones, pero no procesa lógica de negocio.

  • Interfaz de usuario
  • Presentación de datos
  • Recepcion de interacciones
  • No contiene lógica de negocio

Controlador

Actúa como intermediario. Recibe las entradas del usuario, las procesa (posiblemente actualizando el Modelo) y selecciona la Vista apropiada.

  • Maneja peticiones del usuario
  • Actualiza el modelo
  • Selecciona la vista
  • Intermediario entre modelo y vista
→

Modelo notifica cambios a la Vista

→

Vista envía acciones del usuario al Controlador

→

Controlador actualiza el Modelo

Ejemplo Estático: Sistema de Gestión de Usuarios

Veamos cómo funciona MVC en la práctica con un ejemplo de un sistema de usuarios:

Modelo (User.php)

Gestiona los datos de usuario y las operaciones de base de datos:

class User {
  private $id;
  private $name;
  private $email;

  public function __construct($id, $name, $email) {
    $this->id = $id;
    $this->name = $name;
    $this->email = $email;
  }

  public function save() {
    // Lógica para guardar en BD
  }
  public static function find($id) {
    // Lógica para buscar en BD
  }
}

Vista (user_profile.php)

Muestra la información del usuario en una página HTML:

<html>
<body>
  <h1>Perfil de Usuario</h1>
  <div>Nombre: <?= $user->name ?></div>
  <div>Email: <?= $user->email ?></div>
  <form action="index.php" method="POST">
    <input type="hidden" name="action" value="update">
    <button type="submit">Actualizar</button>
  </form>
</body>
</html>

Controlador (UserController.php)

Maneja las peticiones relacionadas con usuarios:

class UserController {
  public function show($id) {
    // Obtener usuario del modelo
    $user = User::find($id);

    // Cargar la vista apropiada
    include 'user_profile.php';
  }

  public function update($id, $data) {
    // Buscar usuario
    $user = User::find($id);

    // Actualizar datos
    $user->name = $data['name'];
    $user->email = $data['email'];

    // Guardar cambios
    $user->save();

    // Redirigir a la vista de perfil
    header("Location: /user/" . $id);
  }
}

Ventajas del Patrón MVC

Separación de preocupaciones

Cada componente tiene una responsabilidad específica, lo que facilita el desarrollo y mantenimiento del código.

Trabajo en equipo

Diferentes desarrolladores pueden trabajar simultáneamente en el modelo, vista y controlador.

Reutilización de código

Los modelos y componentes de vista pueden ser reutilizados en diferentes partes de la aplicación.

Facilidad de testing

La separación de componentes permite realizar pruebas unitarias de manera más sencilla y efectiva.

Múltiples vistas

Un mismo modelo puede ser representado por diferentes vistas sin modificar la lógica de negocio.

Mantenibilidad

Los cambios en la interfaz o la lógica de negocio pueden realizarse de manera independiente.
